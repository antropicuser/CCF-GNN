# CCF-GNN — Screened Time-Lagged Correlation Graphs for Interpretable Traffic Forecasting

Official implementation and reproduction kit for the paper:

> **How Reliable Are Time-Lagged Correlation Graphs for Traffic Forecasting? An Empirical Audit
> and the Screened-Hybrid CCF-GNN**
> Morteza Farid Agh Ghaleh, Ebrahim Akbari, Homayoon Motameni

The repository contains (1) an **empirical audit** of lagged-correlation (Granger/CCF-type)
graph construction on real and synthetic traffic data, and (2) **CCF-GNN**, a forecaster whose
adjacency blends the screened statistical prior with a learnable residual through per-edge
gates, and whose explanations are read directly off validated graph statistics.

## What's inside

```
ccf_graph.py             windowed CCF graph construction on real METR-LA
                         (effect-size + BH-FDR + path-based confound screen + degree cap)
synthetic_recovery.py    synthetic ground-truth benchmark (real road topology, known
                         time-lagged edges + latent confounders) and stage-wise recovery
prepare_npz.py           one-time parquet -> npz conversion (memory-lean)
data_utils.py            loaders, masked DCRNN-style metrics, graph loading
models/ccf_gnn.py        lag-grouped GCN + GRU with masked hybrid adjacency
models/gwnet.py          compact Graph WaveNet baseline (same budget)
train.py                 training/evaluation driver (modes: full, nolag, nohybrid, gwnet, ha)
make_tables.py           regenerates LaTeX tables from results/runs*.json
make_synthetic_table.py  regenerates the synthetic-recovery table/figure
count_params.py          parameter counting (guards efficiency claims)
audit_distance_lag.py    road-distance vs. lag audit by screen verdict (real data)
explainer_demo.py        deterministic template explanations from real graph tuples
make_figures.py          generates ALL paper figures from result JSON/NPZ/CSV artifacts
robustness_eval.py       random node-masking robustness on saved checkpoints
run_pilot.sh             reduced-scale pilot (CPU, ~30 min)
run_medium.sh            medium-scale comparison (CPU, several hours)
results/                 real outputs backing every number in the paper
data/                    sensor graph, sensor coordinates, road distances (distances.csv),
                         id mapping — everything needed to verify graph claims offline
```

## Verify every paper claim (reviewer entry point)

Every table and figure in the paper is regenerated by a script from `results/` — which ships
with this repository, together with the trained checkpoints. **No download is needed** for
items 1–5 below; only full retraining (item 6) re-downloads METR-LA.

| # | Paper claim | Command | Expected result | Runtime |
|---|---|---|---|---|
| 1 | Real graph anatomy (Table 1, Fig. 2–3): 24,179 raw edges, median lag ≈15 min, 16,181 validated (feas. 22.7%), 33% confounded | `python make_figures.py` (uses shipped `results/ccf_graph.npz`) | `figures/fig2_anatomy.pdf`, `fig3_map.pdf` | ~10 s |
| 2 | Distance–lag audit (Table 2): validated ρ_s=0.273 vs confounded 0.176 | `python audit_distance_lag.py` | `results/distance_lag_audit.json` + `paper_tables/distance_audit.tex` | ~30 s |
| 3 | Synthetic ground-truth recovery (Table 3, Fig. 4): deployed P=0.286±0.016, R=0.573±0.032, F1=0.381, exact lag ≈99.5% | `python make_synthetic_table.py`; full rerun: 3×`SYN_SEED=$s python synthetic_recovery.py` | same numbers in `paper_tables/synthetic.tex` | ~5 s (table) / ~15 min (rerun) |
| 4 | Medium-scale same-budget comparison (Table 4, Fig. 5): CCF-GNN 3.51/4.12/5.11 vs GWNet 4.09/4.45/4.94 (15/30/60 min) | `python make_medium_table.py` | `paper_tables/medium.tex` from shipped `results/runs.json` | ~1 s |
| 5 | Robustness to sensor masking (Table 5, Fig. 6): +1.2/+3.7/+3.0% vs +0.3/+1.7/+2.1% | `python robustness_eval.py` (shipped checkpoints `results/ckpt_*.pt`) | `results/robustness.json` — same numbers | ~25 min CPU |
| 6 | Full retraining from scratch (optional) | `python download_data.py && python prepare_npz.py && bash run_medium.sh && python make_medium_table.py` | reproduces item 4 within seed noise | several hours CPU |

Grounded real explanations (sensor 101 example): `python explainer_demo.py` →
`results/example_explanations.json`, `paper_tables/examples.tex` (~5 s).

## Quick start

```bash
pip install -r requirements.txt          # CPU torch is sufficient

# 1) download METR-LA (standard 70/10/20 split + sensor graph)
python download_data.py                  # or fetch manually from witgaw/METR-LA on HF

# 2) build the real-data CCF graph (writes results/graph_stats.json + paper table)
python ccf_graph.py

# 3) synthetic ground-truth recovery (3 seeds, ~15 min CPU)
for s in 0 1 2; do SYN_SEED=$s python synthetic_recovery.py; done
python aggregate_synthetic.py            # included in make_synthetic_table.py flow
python make_synthetic_table.py

# 4) training
python prepare_npz.py                    # one-time
bash run_pilot.sh                        # fast end-to-end verification
bash run_medium.sh                       # same-budget model comparison
python audit_distance_lag.py             # road-distance vs lag audit
python explainer_demo.py                 # real template explanations
python robustness_eval.py                # node-masking robustness (needs run_medium.sh ckpts)

# 5) tables
python make_tables.py
```

## Honest-scope statement

* The paper's **audit results** (real-data graph anatomy, synthetic recovery) are fully
  reproducible on CPU with this repository; the shipped `results/` files are the exact ones
  used in the manuscript.
* The **reduced/medium-scale training comparisons** are reproducible on CPU but are explicitly
  scoped in the paper as reduced-protocol; the full GPU protocol (10 seeds, all baselines) is
  described in the paper and left as the community-facing benchmark run.
* We make **no claim** that CCF-GNN sets accuracy records; its value is the screened,
  interpretable structure and grounded explanations. See the paper's Section 5 for the
  precise wording.

## Data

METR-LA / PEMS-BAY: released with DCRNN (Li et al., 2018); the pipeline consumes the standard
`train/val/test.parquet` + `sensor_graph/` files (see `download_data.py`).
PeMSD4/7/8: released with STSGCN (Song et al., 2020).
